# cc-clinic-lab · 临床试验访视采集台

数据工程产品线基线。题号前缀 `clinic-*`，默认端口 **7600**。

## 技术栈

- 后端：CherryPy + SQLite
- 前端：原生 JS SPA（顶栏薄荷绿丝带导航）
- 会话：itsdangerous 签名 Cookie
- 测试：pytest + httpx（依赖已列入 requirements）

## 登录

- 地址：`http://127.0.0.1:7600/login`
- 账号：`admin` / `123456`

## 页面

| 页面 | 能力 |
|------|------|
| 试验中心 | 中心登记、启停/观察、配额、方案版本生效 |
| 访视批次 | 开批、模拟抓取、追加访视行、合格入库、收齐/关闭 |
| 字段质控 | 按批/全量扫描、发现关闭/重开 |
| 缺口补采 | 排队、执行成功/失败、失败重试 |
| 访视对账 | 缺口/发现/补采对照、中心矩阵、审计 |
| 台参数 | 设置读写 |

## 主链

中心 → 访视批次抓取 → 质控发现 → 缺口补采 → 对账报告；设置与审计贯穿写操作。

## 换版兼容（甲路：物化落点 / 切流账册）

方案换版后，抓取管道、字段质控扫描与补采排队都先对照换版兼容落点表
`compat_cut_landings` 的 `landed` 行放行：

- 落点行钉住当刻**字段版号**与**指纹**（版号 + 必填字段 + 访视编码的 SHA-256），
  读侧只认该行，并置 `read_track=cutover_book`、`reject_refresh=1`。
- 兼容徽标只作展示；徽标亮起但缺落点行、指纹拧花、字段版号漂移三种情形一律判未对齐，
  挡下错列灌批与质控补采（HTTP 409 并给出原因）。
- 落台提交即刻写完入库；同一当刻口径幂等，并发落台由唯一索引 + `BEGIN IMMEDIATE`
  保证只留一行 `landed`，不会双成功互相踩掉钉点。

中心列表页展示兼容徽标、字段版号与落点行次三者对照；其余页面不再重复该读轨。

## 本地

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pytest
python run.py
```

Docker：`docker compose up -d --build`，健康检查打 `/login`。
